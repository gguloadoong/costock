## ADR-001: 프로젝트 시작 및 기본 방향 확정

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 이준혁 (PM), 최재원 (BE), 김민준 (FE), 한서준 (Strategist)

### 컨텍스트
투자정보 서비스 시장에서 주식과 코인을 모두 커버하는 통합 플랫폼이 부재한 상황. CoStock은 이 기회를 공략한다.

### 결정
1. **주식+코인 통합 정보 서비스**로 포지셔닝
2. **MVP 범위**: 국내 주식(코스피/코스닥) + 코인(업비트 원화마켓) 실시간 가격 정보
3. **기술 스택**: Next.js 14 + Fastify + TimescaleDB + Kafka
4. **데이터 소스**: 한국투자증권 Open API(주식) + 업비트 WebSocket(코인) 이원화

### 대안 검토
- **대안 A**: 주식만 먼저 (토스증권 경쟁) → 기각: 차별화 부족
- **대안 B**: 코인만 먼저 (업비트 경쟁) → 기각: 거래소 없이 정보만으론 약함
- **대안 C**: 주식+코인 통합 → **선택**: 블루오션, 차별화 명확

### 결과
Phase 0 (MVP) 개발 착수. 6개월 내 베타 출시 목표.

## ADR-002: 한국 금융 색상 관행 적용

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 박소연 (Designer), 이준혁 (PM)

### 컨텍스트
한국 금융 시장은 상승=빨강, 하락=파랑 관행. 글로벌(미국/유럽)과 반대.

### 결정
한국 관행을 따른다: **상승 #E84040 (빨강), 하락 #2563EB (파랑)**

### 근거
- 타겟 사용자가 100% 한국 투자자
- 기존 습관과 다른 색상 사용 시 혼란 및 이탈
- 네이버증권, 토스증권, 업비트 모두 동일 관행

## ADR-003: 실시간 데이터 아키텍처 — Kafka 채택

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 최재원 (BE)

### 컨텍스트
수만 클라이언트에게 실시간 가격을 브로드캐스트해야 함.

### 결정
Apache Kafka를 메시지 버스로 사용. 수집 서비스 → Kafka → WebSocket 서버 구조.

### 대안 검토
- **Redis Pub/Sub**: 간단하지만 메시지 유실 가능성, 확장성 한계
- **Kafka**: 메시지 보존, 컨슈머 그룹, 수평 확장 → **선택**

### 트레이드오프
- 복잡도 증가 vs 안정성/확장성 확보
- 초기에는 오버엔지니어링일 수 있으나, 트래픽 급증 대비

## ADR-004: TimescaleDB 도입 — 시계열 주가 저장

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 최재원 (BE)

### 결정
PostgreSQL 확장인 TimescaleDB를 시계열 주가 저장에 사용.

### 근거
- 일반 PostgreSQL 대비 시계열 쿼리 10-100배 성능 향상
- 기존 PostgreSQL 생태계 그대로 활용 가능
- 연속 집계(continuous aggregates)로 캔들 데이터 사전 계산
