## ADR-001: 프로젝트 시작 및 기본 방향 확정

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 이준혁 (PM), 최재원 (BE), 김민준 (FE), 한서준 (Strategist)

### 컨텍스트
투자정보 서비스 시장에서 주식과 코인을 모두 커버하는 통합 플랫폼이 부재한 상황. CoStock은 이 기회를 공략한다.

### 결정
1. **주식+코인 통합 정보 서비스**로 포지셔닝
2. **MVP 범위**: 국내 주식(코스피/코스닥) + 코인(업비트 원화마켓) 실시간 가격 정보
3. **기술 스택**: Next.js 14 + Fastify + TimescaleDB + Kafka
4. **데이터 소스**: 한국투자증권 Open API(주식) + 업비트 WebSocket(코인) 이원화

### 대안 검토
- **대안 A**: 주식만 먼저 (토스증권 경쟁) → 기각: 차별화 부족
- **대안 B**: 코인만 먼저 (업비트 경쟁) → 기각: 거래소 없이 정보만으론 약함
- **대안 C**: 주식+코인 통합 → **선택**: 블루오션, 차별화 명확

### 결과
Phase 0 (MVP) 개발 착수. 6개월 내 베타 출시 목표.

## ADR-003: 실시간 데이터 아키텍처 — Kafka 채택

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 최재원 (BE)

### 컨텍스트
수만 클라이언트에게 실시간 가격을 브로드캐스트해야 함.

### 결정
Apache Kafka를 메시지 버스로 사용. 수집 서비스 → Kafka → WebSocket 서버 구조.

### 대안 검토
- **Redis Pub/Sub**: 간단하지만 메시지 유실 가능성, 확장성 한계
- **Kafka**: 메시지 보존, 컨슈머 그룹, 수평 확장 → **선택**

### 트레이드오프
- 복잡도 증가 vs 안정성/확장성 확보
- 초기에는 오버엔지니어링일 수 있으나, 트래픽 급증 대비

## ADR-004: TimescaleDB 도입 — 시계열 주가 저장

**날짜**: 2026-03-18
**상태**: 승인됨
**결정자**: 최재원 (BE)

### 결정
PostgreSQL 확장인 TimescaleDB를 시계열 주가 저장에 사용.

### 근거
- 일반 PostgreSQL 대비 시계열 쿼리 10-100배 성능 향상
- 기존 PostgreSQL 생태계 그대로 활용 가능
- 연속 집계(continuous aggregates)로 캔들 데이터 사전 계산

## ADR-005: 카피트레이딩 = 알림 구독으로 정의 (자동 매매 실행 없음)

- **날짜**: 2026-03-19
- **상태**: 결정됨
- **결정자**: 이준혁 (PM), 한서준 (Strategist)

### 맥락
초기 기획에서 "카피트레이딩"은 AI 트레이더의 매매를 사용자 계좌에 자동으로 복제 실행하는 기능으로 정의되었다. 그러나 이는 자본시장법상 일임 운용 라이선스(투자일임업 등록)가 필요한 영역이며, MVP 단계에서 법적 리스크를 감수하기 어렵다. 또한 실제 자금이 오가는 자동 매매는 신뢰 구축 이전에 출시할 경우 사용자 피해 및 서비스 중단 리스크가 크다.

### 결정
"카피트레이딩"을 **알림 구독 서비스**로 재정의한다. AI 트레이더의 매매 신호가 발생하면 구독한 사용자에게 Web Push 알림을 발송하며, 실제 매매 실행은 사용자가 직접 한다. 자동 주문 집행 기능은 MVP 범위에서 완전히 제외한다.

### 결과
- 투자일임업 등록 불필요 → 즉시 서비스 운영 가능
- 백로그에서 자동 실행 관련 항목 전체 제거 (backlog.md v2.1 반영)
- 사용자가 판단 주체로 유지되어 금융소비자보호법 리스크 최소화
- 향후 트래픽/신뢰 확보 후 Phase 2에서 자동 실행 재검토 가능

## ADR-006: 가격 데이터 소스 확정 — KIS(국내주식) / yahoo-finance2(미국주식) / 업비트(코인)

- **날짜**: 2026-03-19
- **상태**: 결정됨
- **결정자**: 최재원 (BE), 이준혁 (PM)

### 맥락
세 자산군(국내주식/미국주식/코인)의 실시간 가격 수집을 위해 각각 데이터 소스를 확정해야 했다. MVP 일정 내에 무료 또는 저비용으로 빠르게 통합 가능한 소스가 필요했다.

### 결정
- **국내주식**: 한국투자증권 Open API (KIS) — WebSocket 실시간 시세, 무료 테스트 계좌 활용
- **미국주식**: `yahoo-finance2` npm 라이브러리 — API 키 불필요, 즉시 통합 가능
- **코인**: 업비트 WebSocket Open API — 원화 마켓 실시간 체결가, 무료

### 대안 검토
- 미국주식 Polygon.io: 실시간 정확도 높으나 유료 플랜 필요 → Phase 1에서 재검토
- 미국주식 Alpha Vantage: 무료이나 분당 호출 제한(5회)으로 실시간 불가 → 기각
- 코인 바이낸스: 글로벌 거래량 1위이나 원화 마켓 없음, 환율 변환 필요 → Sprint 2에서 선택적 추가

### 결과
- 가격 데이터 3원화 구조 확립: KIS + yahoo-finance2 + 업비트
- MVP 비용 $0 (KIS 무료 계좌, yahoo-finance2 무료, 업비트 Open API 무료)
- yahoo-finance2는 비공식 API 특성상 구조 변경 리스크 존재 → Phase 1 Polygon.io 전환 예정

## ADR-007: PWA (Next.js) 선택 — React Native / 앱스토어 배포 제외

- **날짜**: 2026-03-19
- **상태**: 결정됨
- **결정자**: 이준혁 (PM), 김민준 (FE)

### 맥락
모바일 우선 투자 정보 앱으로서 네이티브 앱(React Native)과 PWA 중 플랫폼을 선택해야 했다. 출시 속도, 팀 역량, 앱스토어 심사 리스크를 종합 고려했다.

### 결정
**Next.js 14 기반 PWA**로 출시한다. 앱스토어(App Store / Play Store) 등록 없이 웹 URL로 배포하며, manifest.json + Service Worker로 홈 화면 추가 및 Web Push를 지원한다.

### 대안 검토
- React Native: 네이티브 성능 우수, 앱스토어 배포 가능 → 앱스토어 심사 2~4주 소요, 금융 앱 추가 심사 리스크, 팀 내 RN 경험 없음 → 기각
- Expo: RN 진입장벽 낮추나 동일한 앱스토어 문제 → 기각
- Flutter: 크로스플랫폼 성능 우수 → 기술 스택 전환 비용 과대, 기각

### 결과
- 앱스토어 심사 없이 즉시 배포 가능 → 출시 속도 확보
- 팀 전원 Next.js/React 경험 보유 → 생산성 극대화
- Web Push는 iOS Safari 16.4+ 지원으로 주요 타겟 커버 가능
- Phase 1에서 사용자 반응 데이터 기반으로 React Native 전환 재검토 (FE-P1-003)

## ADR-008: AI 트레이더 5인 체계 확정 — 알파/베타/감마/델타/엡실론

- **날짜**: 2026-03-19
- **상태**: 결정됨
- **결정자**: 이준혁 (PM)

### 맥락
초기 기획은 AI 트레이더 3인(알파/베타/감마)으로 시작했으나, 다양한 투자 성향과 자산군을 커버하기 위해 라인업 확장이 논의되었다. MVP 단계에서 몇 명의 트레이더로 출시할지, 각 트레이더의 전략 캐릭터를 어떻게 정의할지 결정이 필요했다.

### 결정
**5인 체계**로 확정한다. 각 트레이더의 전략 포지셔닝은 다음과 같다.

| 트레이더 | 별칭 | 전략 유형 | 주요 자산 |
|---------|------|----------|---------|
| AI-알파 | 모멘텀 헌터 | 모멘텀 (RSI, 거래량, 기관 순매수) | 국내주식 |
| AI-베타 | 역추세 사냥꾼 | 역추세 (볼린저밴드, Fear&Greed) | 코인 |
| AI-감마 | 퀀트 팩터 | 팩터 (PER/ROE/부채비율) | 국내주식 |
| AI-델타 | 매크로 서퍼 | 매크로 (금리/환율/글로벌 지수) | 미국주식 + 코인 |
| AI-엡실론 | 센티멘트 리더 | 감성 분석 (뉴스/소셜 센티멘트) | 전 자산 |

모든 트레이더는 2026-03-01 기준 백필 시뮬레이션 데이터로 초기 성과 이력을 구성한다.

### 결과
- 5종 아바타(TraderAvatar) 디자인 완료 (DS-005 확장)
- 투자 성향별 트레이더 선택 UX 제공 → 사용자 페르소나 매칭 가능
- 초기 6인 계획에서 AI-제타(리스크패리티) 제외 → MVP 집중도 유지
- 백필 시뮬레이션으로 신규 사용자에게 충분한 성과 이력 제공 가능
