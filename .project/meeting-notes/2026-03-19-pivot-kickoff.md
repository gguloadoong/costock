**날짜**: 2026-03-19 (목) 10:00 ~ 12:10
**장소**: 강남 작업실 회의실 A
**참석자**: 이준혁(PM), 박소연(Designer), 김민준(FE), 최재원(BE), 정예린(QA), 한서준(Strategist)
**작성자**: 이준혁

## 회의 목적

기존 CoStock v1 (주식+코인 통합 정보 플랫폼) 방향을 전면 피봇, AI 트레이더 카피트레이딩 플랫폼으로 전환하는 킥오프 미팅.

## 의사결정 요약 (앞에 놓기)

1. 피봇 확정. 기존 v1 코드베이스는 일부 재활용, 기획/디자인은 전면 새로 작성.
2. Phase 0 MVP: AI 3개(알파/베타/감마) + 피드 + 알림 + 포지션 뷰. 8주.
3. 카피트레이딩 자동 실행은 법무 검토 후 Phase 1. MVP 미포함.
4. 미국주식 AI(감마)는 MVP에 포함하되 Yahoo Finance 비공식 API 우선 사용, Phase 1에서 Polygon.io 전환.
5. 면책 고지 문구 외부 법무 자문 선행 (이준혁 + 한서준 담당, 2주 내).

## 전체 진행

### 1부 — 피봇 배경 발표 (이준혁, 10:00~10:30)

**이준혁**: 지난 3주 사용자 인터뷰 12건 결과부터 공유할게요. v1 컨셉(주식+코인 통합 정보) 보여줬을 때 반응이 "오 편리하겠다"인데, 계속 써야 할 이유를 못 찾겠다는 게 공통이었어요. 네이버 금융이나 토스에서 가격 보는 건 이미 잘 하고 있고, 두 자산을 한 앱에서 본다는 게 그다지 강한 이유가 안 됐습니다.

반면 "AI가 실제로 투자하는 걸 볼 수 있다면?"이라고 물었을 때 12명 중 9명이 눈이 커졌어요. 특히 "지금까지 뭘 사야 할지 몰라서 손도 못 댔는데, AI 따라하면 되면 해볼 수 있을 것 같다"는 발언이 세 명한테서 나왔습니다. 이게 피봇의 근거입니다.

eToro가 글로벌에서 3,500만 사용자를 만든 모델이 카피트레이딩인데, 국내에는 이걸 제대로 하는 서비스가 없어요. 에임이나 핀트는 있지만 AI가 무엇을 하는지를 투명하게 보여주지 않아요. CoStock은 AI 행동 자체를 콘텐츠로 만들겠습니다.

**한서준**: 한 가지 덧붙이면, 저번 주에 시장 리서치 해봤는데 국내 "자동매매" "퀀트 투자" 관련 유튜브 채널 구독자 합산이 180만을 넘어요. 관심은 있는데 진입 장벽이 너무 높은 거거든요. 우리가 그 진입 장벽을 없애주는 거라고 보면 됩니다.

---

### 2부 — 기능 스펙 리뷰 (이준혁, 10:30~11:00)

**이준혁**: PRD 초안을 오전에 공유드렸는데 각자 보면서 피드백 해주세요.

**박소연**: 피드 화면이 핵심인 거 맞죠? 트위터/X 같은 타임라인 구조 염두에 두고 있었는데, AI가 "매수했다"는 카드가 계속 흘러내려가는 형태로 가면 되겠네요. 근거 텍스트가 1~2줄이라는 게 중요한 것 같아요. 너무 길어지면 안 읽히니까. 폰트 크기나 강조 방식은 제가 A/B 두 가지로 먼저 만들어볼게요.

**이준혁**: 맞아요. 텍스트가 길면 스크롤 리듬이 깨지거든요. 근거는 1줄이 이상적인데 LLM이 2줄까지 내뱉는다고 하면 UI에서 말줄임으로 처리하고, 탭하면 전체 보기 하는 구조도 고려해봐요.

**김민준**: 기술적으로 보면 WebSocket을 항상 열어두면 배터리 이슈가 생길 수 있어요. 앱이 포그라운드에 있을 때만 연결하고, 백그라운드는 FCM 알림으로 처리하는 게 맞을 것 같습니다. iOS는 백그라운드 소켓 제한도 있고.

**최재원**: 동의해요. 피드 WebSocket은 포그라운드 전용으로 하고, 백그라운드 알림은 서버에서 FCM/APNS 쏘는 별도 채널로 분리하면 됩니다. 구조적으로도 깔끔하고.

**이준혁**: 좋아요. 그렇게 설계해주세요.

---

### 3부 — AI 트레이더 설계 논의 (최재원 + 이준혁, 11:00~11:30)

**최재원**: AI 알고리즘 관련해서 확인하고 싶은 게 있어요. 알파(모멘텀)는 52주 신고가 + 거래량 급증인데, 국내주식은 한국투자증권 API로 실시간 데이터 끌어올 수 있어요. 문제는 미국주식 감마예요. Yahoo Finance 비공식 API는 장기적으로 막힐 수 있거든요. Polygon.io 계약을 처음부터 가는 게 나을 수도 있어요.

**한서준**: Polygon.io 스타터 플랜이 월 29달러인데, MVP 기간에 우선 야후 파이낸스로 가고 Phase 1에서 전환하는 게 좋을 것 같아요. 그사이 Polygon 계약 협의 진행할게요. 데이터 안정성 SLA가 필요한 시점에 맞춰서.

**최재원**: 그러면 감마 알고리즘은 일단 일별 종가 기준으로 돌아가는 버전으로 만들고, Polygon으로 가면 실시간으로 업그레이드하는 방식으로. 월 1회 리밸런싱이 로직이니까 사실 일별 종가도 충분해요.

**이준혁**: 감마는 그렇게 가요. 다음 — AI가 매매 근거 텍스트를 생성할 때 OpenAI API 쓰는 거 맞죠?

**최재원**: 네. 매매 신호 발생할 때마다 LLM 호출하면 비용이 나가긴 하는데, 피드 카드 하나당 1~2회 호출이고 초기에 트레이딩 빈도가 하루 10~20건 수준이면 월 몇 천원 수준이에요. 문제없어요.

**박소연**: AI 트레이더 아바타 이야기를 좀 해야 할 것 같아요. 숫자/문자만 있으면 재미없잖아요. 알파는 좀 공격적인 이미지, 베타는 차분한, 감마는 학자 스타일 이런 식으로 캐릭터성을 주면 팔로우할 때 감정적인 연결이 생길 것 같은데요.

**이준혁**: 완전 동의. 아바타 6종 디자인 백로그에 넣읍시다. 에이전시에 맡기기엔 시간이 빠듯하니까 소연씨가 직접 가져가는 걸로.

**박소연**: 알겠어요. 일러스트 스타일 두 가지 방향으로 먼저 시안 잡아볼게요.

---

### 4부 — 법적 고려사항 (한서준 + 이준혁, 11:30~11:50)

**한서준**: 제일 중요한 이슈가 투자 권유 문제예요. 자본시장법상 투자 권유는 인가받은 금융투자업자만 할 수 있거든요. 우리가 "AI가 삼성전자 샀어요, 따라하세요"라고 하면 권유로 볼 여지가 있어요.

**이준혁**: 그래서 포지셔닝을 "AI 모의투자 정보 서비스"로 명확히 해야 해요. 실제 돈을 운용하는 게 아니고, 정보 제공이라는 것. 면책 고지를 모든 화면 하단에 고정하는 것도 그래서예요. "본 서비스는 AI 모의투자 정보 제공 서비스입니다. 투자 권유가 아닙니다."

**정예린**: 그런데 카피트레이딩 자동 실행 기능은 어때요? 사용자 계좌에서 자동으로 주문이 나가면 이게 일임 운용 아닌가요?

**한서준**: 맞아요. 그게 핵심 법적 리스크예요. 일임 운용은 투자일임업 라이선스가 필요한데, 우리가 MVP에 자동 실행을 안 넣는 이유가 바로 그거예요. Phase 1에서 할 때도 "사용자가 버튼을 직접 눌러서 실행"하는 준자동 형태로 가거나, 금융위에 유권해석 먼저 받아야 해요.

**이준혁**: 외부 법무 자문 일정 잡는 거, 한서준씨가 2주 내로 세팅해줄 수 있어요?

**한서준**: 네. 핀테크 전문 법무법인 두 곳에 이미 컨택 해뒀으니까 다음 주 안으로 미팅 잡겠습니다.

**이준혁**: 좋아요. 면책 문구 초안은 제가 먼저 써서 공유할게요. 법무 검토 받기 전 내부 초안 버전으로.

---

### 5부 — QA 전략 및 데이터 품질 (정예린, 11:50~12:05)

**정예린**: QA 관점에서 이번 서비스는 가격 데이터 정합성이 제일 중요한 것 같아요. AI 수익률 계산이 틀리면 사용자 신뢰가 한 번에 무너지니까. 매수가/현재가/슬리피지 계산이 맞는지 검증하는 자동화 테스트를 백엔드 개발 초기부터 같이 넣고 싶어요.

**최재원**: 좋아요. API 레벨에서 수익률 계산 함수를 단위 테스트로 먼저 만들어놓을게요. QA 시나리오 기반으로 테스트케이스 같이 정의해요.

**정예린**: 그리고 알림 지연 측정도 체계적으로 해야 해요. AI 신호 발생 시점 타임스탬프와 FCM 수신 시점 차이를 로그로 남기는 구조를 처음부터 설계해주세요.

**최재원**: 넣겠습니다. 알림 서버에 발송/수신 타임스탬프 로그 테이블 설계할게요.

**정예린**: 마지막으로 이상값 필터 검증이요. ±20% 급변 필터가 실제로 동작하는지, 그리고 정상 급등(예: 뉴스 호재로 진짜 15% 올랐을 때)에서 오탐이 나지 않는지 시나리오 잡아야 해요. 임계값 조정이 필요할 수 있어요.

**이준혁**: ±20%는 일단 시작점이고, 운영하면서 조정하는 걸로. 정예린씨가 오탐 케이스 모아서 리포트해줘요.

### 6부 — 스프린트 계획 확정 (이준혁, 12:05~12:10)

**이준혁**: 8주 플랜 정리해서 공유할게요. 스프린트 4개, 2주씩. S1은 인프라 + 디자인 기반 잡기, S2는 AI 알고리즘 + 핵심 API, S3는 앱 화면 완성 + 알림, S4는 통합 QA + 베타 배포예요. TestFlight 100명 베타 목표는 5월 14일.

**김민준**: React Native로 가는 거 맞죠? Expo 기반으로.

**이준혁**: 네. iOS/Android 동시 개발이 필요하고, 초기에 네이티브 퍼포먼스 이슈가 생길 정도로 복잡한 기능은 없으니까요.

**김민준**: 알겠습니다. 그러면 이번 주 안에 Expo 프로젝트 셋업하고 탭 내비게이션까지 잡아놓을게요.

**박소연**: 저도 이번 주 안에 DS-001 (디자인 시스템 토큰) 완성하고 온보딩 시안 3장 올릴게요. Figma 링크 슬랙에 공유할게요.

**최재원**: 업비트/바이낸스 WebSocket 연동은 저도 이번 주 안에 PoC(Proof of Concept) 수준으로 돌려볼게요. 실제 데이터 들어오는 거 확인하고 BE-004 스키마 설계 들어가겠습니다.

**이준혁**: 완벽해요. 다음 스탠드업은 내일 오전 10시. 각자 오늘 할 일 슬랙에 올려주세요.
