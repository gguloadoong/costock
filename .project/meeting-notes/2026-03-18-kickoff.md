## 1. 서비스 비전 (이준혁)

### 핵심 문제 정의

> "주식 앱과 코인 앱, 둘 다 켜는 번거로움을 없앤다."

1. **앱 전환 마찰**: 주식+코인 정보 확인을 위해 평균 2~5개 앱을 오감
2. **크로스에셋 시각 부재**: 코인 시장 흐름과 관련 주식 종목을 연결해주는 서비스가 국내에 없음
3. **포트폴리오 파편화**: 주식 수익률은 MTS, 코인 수익률은 거래소 앱에서 따로 확인

**포지션**: 거래 중개 아님, 정보 플랫폼. 규제 리스크 최소화.

### 목표 사용자

| 페르소나 | 김도현 (26세, 개발자) | 박정숙 (45세, 중소기업 임원) |
|----------|----------------------|------------------------------|
| 자산 | 코인 1,200만 + 주식 300만 | 주식 8,000만 + 코인 200만 |
| 불편점 | 코인 급등 시 관련주 확인에 앱 4개 열어야 함 | 코인 정보 어디서 봐야 할지 모름 |
| 원하는 것 | 크로스에셋 연관 정보, 통합 수익률 | 주식 인터페이스에서 자연스럽게 코인 확인 |
| 역할 | 초기 유입 채널 (코인 커뮤니티 바이럴) | 장기 리텐션 담당 |

### 경쟁사 대비 차별화

| 경쟁사 | 공백 | CoStock |
|--------|------|---------|
| 토스증권 | 코인 정보 없음 (의도적 제외) | 코인 실시간 + 연관 분석 |
| 업비트 | 주식 정보 없음, 거래 중개 목적 | 정보 제공, 거래 경쟁 아님 |

**지속 가능한 차별화**: 크로스에셋 데이터 누적, 중립적 포지션, 통합 UX 선점

## 6. 기술 아키텍처 (최재원)

### 실시간 데이터 파이프라인

```
업비트 WS / KRX REST
        ↓
   Kafka (crypto.raw / stock.raw)
        ↓
   Normalizer (validated 토픽)
        ↓
   TimescaleDB (hypertable)
   Redis (최신가 캐시, TTL 30초)
        ↓
   Fastify API (REST + WebSocket)
        ↓
   클라이언트
```

### 기술 스택 결정

| 계층 | 기술 | 선택 이유 |
|------|------|-----------|
| API 서버 | Fastify (Node.js, TypeScript) | 고성능, 구조화 로거(pino), 플러그인 생태계 |
| DB | PostgreSQL + TimescaleDB | 시계열 hypertable, 연속집계, 보존 정책 |
| 캐시 | Redis | MGET 배치로 N+1 방지, TTL 기반 스테일 방어 |
| 메시지 큐 | Kafka | 수집기-서버 디커플링, 순서 보장 |
| 인프라 | AWS ECS Fargate | 서버리스 컨테이너, 자동 스케일링 |

### 구현된 개발 환경 (`/Users/bong/costock/`)

- `docker-compose.yml` — PostgreSQL+TimescaleDB, Redis, Kafka
- `apps/api/` — Fastify REST + WebSocket 서버
- `apps/collector/` — 업비트 WebSocket → Kafka 수집기 (Python)
- `scripts/setup-dev.sh` — 원클릭 초기화
- TypeScript 타입 체크 0 에러, 하드코딩 시크릿 없음 확인

**지금 바로 테스트 가능**: `bash scripts/setup-dev.sh` → `GET /api/v1/prices/latest`

### 주요 기술 리스크

1. 한국투자증권 API 승인 지연 → 최재원이 이번 주 내 상태 확인
2. 업비트 WebSocket 간헐적 끊김 → 지수 백오프 재연결 로직 Day 1부터 구현 완료

## 7. QA 전략 (정예린)

### 핵심 QA 리스크

| 리스크 | 심각도 | 대응 |
|--------|--------|------|
| 가격 0원/음수 표시 | Critical | 이상값 필터, 직전 유효값 유지 |
| 스테일 데이터 최신 오인 | Critical | 3초 미갱신 시 비활성 UI |
| 멀티화면 가격 불일치 | High | E2E 자동 비교 테스트 |
| 상한가/하한가 오필터링 | High | 전일 종가 기준 계산 (직전 틱 기준 금지) |

### 테스트 피라미드

- 단위(50%): Vitest — 가격 포맷, 이상값 필터 커버리지 100%
- 통합(35%): 실제 API 연결 (DB Mock 금지)
- E2E(15%): Playwright — 10개 핵심 플로우

### 배포 품질 게이트 (5단계)

1. **Gate 1 (CI 자동)**: 단위 테스트 100% 통과, 커버리지 70%+, 보안 스캔 통과
2. **Gate 2 (Staging)**: 통합 테스트, 이상값 필터 TC 100%
3. **Gate 3 (E2E)**: 필수 10개 시나리오 100%
4. **Gate 4 (성능)**: LCP <2.5초, API p99 <500ms, WS 지연 <3초
5. **Gate 5 (수동)**: Critical 버그 0건, QA Lead 사인오프

**장 중(09:00~15:30) 배포 금지** — QA Lead 명시적 승인 없이 불가

### 비기능 요구사항

| 지표 | 목표 |
|------|------|
| REST API p99 | < 500ms |
| WebSocket 가격 전파 | < 3초 |
| 가용성 (장 중) | 99.99% |
| 가용성 (전체) | 99.9% |
| 가격 오표시율 | 0% |
| False Negative (이상값 통과) | 0% |
