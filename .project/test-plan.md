## 1. 테스트 전략 개요

### 테스트 피라미드
```
          ┌──────────┐
          │   E2E    │  ← Playwright (20%)
          │  테스트   │
        ┌─┴──────────┴─┐
        │   통합 테스트  │  ← API 실제 호출 (30%)
        │              │
      ┌─┴──────────────┴─┐
      │    단위 테스트     │  ← Vitest (50%)
      │                  │
      └──────────────────┘
```

### 금융 앱 특화 원칙
1. **가격 데이터 정확성** > 기능 완성도
2. DB mock 금지 — 실제 DB 연결 통합 테스트 필수
3. 장애 시나리오(API 끊김, 이상값) 반드시 테스트
4. 장 개시(09:00) 트래픽 급증 시나리오 포함

## 2. 핵심 리스크 및 테스트 시나리오

### 🔴 Critical — 가격 표시 오류

#### TC-001: 가격 포맷 정확성
```
시나리오: 다양한 가격대 숫자 표시 검증
케이스:
  - 삼성전자 85,400원 → "85,400" (천 단위 콤마)
  - 비트코인 142,850,000원 → "142,850,000"
  - 소수점 종목 → 소수점 2자리 고정
  - 0원 가격 → 표시 금지 + 에러 처리
기대값: 형식 일치, 이상값 필터링
```

#### TC-002: 변동률 부호 표시
```
시나리오: 상승/하락/보합 변동률 표시
케이스:
  - 상승: +1.43% (빨간색, + 부호)
  - 하락: -0.89% (파란색, - 부호)
  - 보합: 0.00% (회색, 부호 없음)
기대값: 부호 + 색상 정확히 일치
```

#### TC-003: 실시간 가격 일관성
```
시나리오: 동일 종목이 여러 화면에서 동일한 가격 표시
검증:
  - 메인화면 관심종목 가격 == 종목상세 현재가
  - 검색 결과 가격 == 종목상세 현재가
  - 2초 이내 동기화
```

### 🔴 Critical — 실시간 데이터 장애

#### TC-010: WebSocket 재연결
```
시나리오: WebSocket 연결이 끊겼다 재연결
단계:
  1. 앱 정상 실행 (가격 업데이트 확인)
  2. 네트워크 강제 차단 5초
  3. 네트워크 복원
  4. 재연결 및 가격 업데이트 재개 확인
기대값:
  - 끊김 즉시 "연결 중..." 표시
  - 30초 이내 재연결 성공
  - 재연결 후 정상 가격 수신
```

#### TC-011: Stale 데이터 표시
```
시나리오: 가격 업데이트가 5초 이상 없을 때
기대값: UI에 "데이터 지연" 또는 마지막 업데이트 시간 표시
금지: 이전 가격을 최신인 것처럼 표시
```

#### TC-012: 외부 API 장애 시 폴백
```
시나리오: 한국투자증권 API 장애 시뮬레이션
기대값: Redis 캐시 데이터로 폴백 + 사용자 안내
```

### 🟡 High — 성능

#### TC-020: 장 개시 트래픽 (09:00)
```
도구: k6
시나리오: 09:00 동시 접속 1만 명 시뮬레이션
기대값:
  - API p99 < 500ms
  - WebSocket 메시지 지연 < 3초
  - 에러율 < 0.1%
```

#### TC-021: Core Web Vitals
```
도구: Lighthouse CI
기준:
  - LCP < 2.5초
  - FID < 100ms
  - CLS < 0.1
측정 페이지: 메인, 종목상세, 검색결과
```

#### TC-022: 장시간 사용 메모리 누수
```
시나리오: 30분 연속 사용
검증: WebSocket 연결 유지, 메모리 증가율 < 10MB/시간
```

### 🟡 High — 보안

#### TC-030: 인증 토큰 검증
```
- 만료된 JWT로 API 호출 → 401
- 변조된 JWT → 401
- 다른 사용자 watchlist 접근 → 403
```

#### TC-031: API Rate Limiting
```
- 1분에 200회 요청 → 429 응답 확인
- Rate Limit 초과 후 1분 대기 → 정상 복귀
```

## 3. 배포 전 품질 게이트 (Definition of Done)

### 기능 출시 필수 조건
- [ ] 모든 P0 기능 TC 통과
- [ ] 가격 포맷 TC (TC-001, TC-002) 100% 통과
- [ ] WebSocket 재연결 TC (TC-010) 통과
- [ ] Lighthouse LCP < 2.5초
- [ ] API p99 < 500ms
- [ ] 보안 스캔 취약점 0건 (Critical/High)
- [ ] 크리티컬 버그 0건

### 코드 품질 기준
- 단위 테스트 커버리지 70% 이상 (핵심 비즈니스 로직 90%+)
- E2E 테스트 주요 플로우 커버: 메인화면 → 검색 → 종목상세 → 즐겨찾기

## 5. 버그 심각도 분류

| 심각도 | 기준 | SLA |
|--------|------|-----|
| Critical | 가격 오표시, 서비스 다운 | 즉시 수정 |
| High | 핵심 기능 불가, 데이터 지연 | 24시간 내 |
| Medium | 부가 기능 오류, UI 깨짐 | 스프린트 내 |
| Low | 텍스트 오탈자, 미세 정렬 | 다음 스프린트 |
